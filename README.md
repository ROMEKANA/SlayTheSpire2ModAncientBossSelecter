# SelectMOD 制作メモ

自分用の日本語メモ。公開用の紹介文ではなく、現状・決めたこと・動かし方・次にやることをここに残す。

最終更新: 2026-11-18（日本時間）。現在は**0.2.0の個別アセンション実装**。A1〜A10のソロ用コードと自動テストを追加済み。0.2.0の実DLLビルド・ゲーム内の効果確認はこれから。0.1.0の設定保存・次回設定分離は手元のレポートで確認済み。

## 作りたいもの

Slay the Spire 2で、Actごとのエンシェントとボスを指定／Ban／候補制限し、アセンション効果を個別にON/OFFできるMOD。例えば「A1はOFF、A2はON」を可能にする。

- BaseLib・RitsuLib・ModConfigなど、別MODへの依存なし。ゲーム標準ローダーと同梱Harmonyを使う。
- マルチ対応を目標に、ホストが設定を編集し、全員が同じラン設定を使う設計にする。
- マルチでは全員が対応するSelectMODを導入する前提。
- セーブ再開では、そのランの保存済み設定と確定済みの出現結果を使う。

MOD ID／DLL名はSelectMOD。現在の版は0.2.0。ソース確認済みSteam Build IDは26660232で、セットアップ時と起動時に参照DLLを照合する。未知のDLLでは導入・初期化を停止する。

## ソロから作るか

**機能の動作確認はソロから進める。設定と保存の構造は最初からマルチを見据えて作る。** ソロなら抽選・表示・A効果の問題を切り分けやすい。一方、ソロ完成後まで同期の調査を遅らせると、保存方法や設定の持ち方を作り直す可能性がある。

週末までは「設定保存のソロ試作 → 手元でビルド・再開確認 → ソロ機能の実装」を進める。ホスト／ゲストの実機試験は週末以降。ソロ試作段階ではマルチ使用を明示的に止め、同期が未完成のまま有効化しない。ソロ専用MODとして完成させてから別物に改造する方針にはしない。

初版の入口は標準のカスタムランを第一候補にする。通常ラン・デイリーは追加検討。標準Modifierの設定・保存・同期を優先し、不足する保証だけ追加する。詳細は[初期設計](DESIGN_AND_LESSONS.md)を参照。

## 今回のレポートで分かったこと

- 標準のラン開始メッセージにModifierの保存プロパティも含まれる。設定を運ぶ経路として標準機構を優先できる。
- 全Actの部屋は開始時にまとめて生成される。最終ActのA10第2ボスは、その外側の処理で追加される。
- 主ボス・第2ボス・エンシェントの確定IDは標準セーブに保存される。公開メソッド経由で出現結果を更新できる経路もある。
- v2で保存プロパティの対応型（整数・真偽値・文字列など）と、セーブ再開時に設定・部屋情報が送られる経路を確認。初回の採取不足と検索の打ち切りは解消した。
- MOD初期化中にモデル一覧のキャッシュを作ると、自分のMODが一覧に入る前に確定する可能性がある。登録確認はロード後に行う。

詳しい根拠と未確認点は[現行ゲームの調査結果](docs/INSTALLED_GAME_REVIEW.md)。v2レポートを受領し、全1586件と追加の保存・通信処理を確認済み。今は再採取不要。ソロ設定保存の基礎確認は完了。以下の導入・ログ回収手順は今後の更新にも使う。マルチ試験は週末以降に保留する。

## 手元のゲームを調査する

WindowsのPowerShellで、このリポジトリのフォルダを開いて実行する。ゲームを終了し、Steamの更新が終わってから行う。

.NET 9 SDKがなければ追加する（調査ツールと本体ビルド用。SDK 10だけではglobal.jsonを満たさない）。

```powershell
winget install --id Microsoft.DotNet.SDK.9 --exact
```

PowerShellを開き直し、リポジトリ直下で調査スクリプトを実行する。

```powershell
.\scripts\Export-GameSources.ps1
```

初回はlocal/paths.txtを作成し、固定版のILSpyCmd 9.1.0.7988をlocal/ilspy9へ導入する（NuGetへの接続が必要）。ゲームDLLを短い一時フォルダ（OSのTEMP配下のsm-*）へ逆コンパイルして関連箇所を抽出するため、数分以上かかる場合がある。ゲームや生成プロジェクトは実行しない。

成功したら **local/selectmod-sources.txt** をこのチャットに送る。内容は以下。

- sts2.dll・0Harmony.dll・GodotSharp.dllのSHA-256、ファイルバージョン、取得可能ならSteam Build ID、runtimeconfig。
- 実在するソースの一覧と、ラン開始・ロード・保存・部屋生成・マップ・アセンション・通信に関係する主要な型。
- HasLevelや抽選・同期処理などの検索結果と前後のコード。既定では最大2500箇所で、打ち切り件数を明記する。完全な呼び出し解析ではない。

セーブ・ゲーム設定・MOD導入先は読み書きしない。変更するのは作業用local/配下、OSのTEMP配下に作成する専用一時フォルダ、指定したパスファイルの初回作成だけ。DLLのハッシュを前後で確認し、失敗・更新検出時は前回の正常レポートを置き換えない。成功時は今回の一時ソースを削除し、前回のレポートは別名で残す。生成ソース・DLL・診断結果はGit対象外。

失敗したら **local/selectmod-export-error.txt** を送る。調査に使った一時ファイルも残す（場所はエラーファイルのPartial output欄）。PowerShell自体に実行を拒否された場合はスクリプトが起動していないため、このエラーファイルは作成されない。

### ゲームの場所が標準と違う場合

local/paths.txtの3行は、ゲームルート、セーブのルート、SelectMODの設定ディレクトリ。既存ファイルは上書きしない。ゲームが見つからなければ、1行目を実際の場所に直して再実行する。調査では2・3行目の場所にはアクセスしない。

パスファイルを開く（リポジトリ直下）。

```powershell
notepad .\local\paths.txt
```

別のパスファイルで調査する場合。

```powershell
.\scripts\Export-GameSources.ps1 -PathsFile 'D:\STS2-settings\paths.txt'
```

書式は[scripts/paths.example.txt](scripts/paths.example.txt)を参照。

### PowerShellの権限エラー

「スクリプトの実行が無効」は実行ポリシー、「署名されていない」は取得元のブロック、「アクセス拒否」は書き込み権限、「使用中」はファイルロックを確認する。

現在のポリシーを確認する（作業フォルダは任意）。

```powershell
Get-ExecutionPolicy -List
```

組織のポリシーで管理されていない場合、信頼できるスクリプトのために現在のPowerShellだけRemoteSignedにする。

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
```

取得元と内容を確認し、エラーで指定されたファイルだけブロックを解除する（例）。

```powershell
Unblock-File -LiteralPath .\scripts\Export-GameSources.ps1
```

MachinePolicy/UserPolicyは上書きしない。調査は通常のユーザー権限で行う。導入時の書き込み拒否では必要に応じて同じWindowsアカウントで昇格し、使用中ならゲームを通常終了する。広範囲のACL変更やプロセスの強制終了はしない。

起動前のポリシー情報をファイルに保存する（localが作成済みの場合、リポジトリ直下）。

```powershell
Get-ExecutionPolicy -List | Out-File -Encoding utf8 .\local\execution-policy.txt
```

## 0.2.0で試せること

ソロのStandardカスタムランに「SelectMOD 個別アセンション」を追加した。ONにするA番号をセットアップ時に指定し、このModifierを選んだランだけに適用する。例えばA2とA4だけON、A1とそれ以外はOFFにできる。

効果の正本はランに保存する設定。ゲームの累積値は開始時にA0へ揃え、選択した効果だけを判定する。A0表示でも個別効果は有効。記録・実績等は標準カスタムランの扱いを維持し、通常の累積アセンションと同等とは扱わない。選ばなければ標準の判定を保つ。0.1.0の「設定保存テスト」と保存済みランも残している。

**この開発版の導入中は、全マルチの開始・再開を停止する。** マルチ実機試験は週末以降。通常ランへの適用、Dread／Blitz、個別アセンション付きのリプレイは今回未対応。ボス／エンシェントの指定機能もまだ未実装。

通常ランでも共通のラン状態・初期化へ渡る経路を確認できている。今回の判定部は画面に依存させず、通常ランへ設定を渡す入口・UI・実績等の扱いを別途追加する方針。通常ランの挙動を変えたとはまだ言わない。[効果経路の調査](docs/ASCENSION_AUDIT.md)を参照。

## ビルド・導入とソロ確認

WindowsのPowerShellでリポジトリ直下から実行する。.NET 9 SDKが必要。ゲームは終了しておく。

リポジトリを更新する。

```powershell
git pull --ff-only origin main
```

A2・A4だけONにして、テスト・実DLLビルド・導入をまとめて行う。

```powershell
.\scripts\Setup.ps1 -Ascensions 2,4
```

ゲーム内で、ソロのカスタムラン→Standard→「SelectMOD 個別アセンション」を選ぶ。説明のON一覧がA2・A4であることを確認する。従来の「設定保存テスト」は効果を変えないので、今回は選ばなくてよい。

1. 新規開始し、A4によりポーション枠が通常より1つ少ないことを確認する。
2. A1はOFF、A2はON。A1は同条件のマップと比較し、A2はエンシェントでの回復経路で確認する。マップ配置や回復後の見た目だけを全効果の証明にはしない。
3. 通常のセーブ・終了後、再起動して同じランを再開する。設定一覧とポーション枠が保持され、初期効果が再び加算されないことを確認する。
4. 次回用設定を変更しても、既存ランの設定は変わらない。新しい効果を試すときは新規ランを開始する。

A5だけを試す場合は、ゲーム終了後に次を実行する。

```powershell
.\scripts\Setup.ps1 -Ascensions 5
```

新規ランの開始デッキに初期呪いが追加され、保存・再起動後に二重追加されないことを確認する。A4はOFFなので枠の減少は起きない想定。A10だけなら-Ascensions 10で新規開始し、最終Actの第2ボスを確認する。

すべてOFFにする（それでも独立モードとして保存する）。

```powershell
.\scripts\Setup.ps1 -Ascensions @()
```

-Ascensionsを省略した更新では既存のON一覧を保持する。初回・0.1.0からの設定追加時は全OFF。未指定の効果はOFFで、同じ番号を重複指定しても一度だけ扱う。現時点で番号変更はこのコマンドから行い、ゲーム画面では設定済みModifierをON/OFFする。

セットアップ・起動・効果判定・再開のログを1ファイルにまとめる。

```powershell
.\scripts\Export-ProbeReport.ps1
```

**local/selectmod-probe.txt** と、確認できた実効果（ポーション枠／初期呪いなど）を送る。ビルド失敗時も同じコマンドでコンパイル出力を回収できる。ASCENSION_CHOICEは新規設定、ASCENSION_BOUNDはランへの固定と判定値照合、ASCENSION_CREATED／LOADEDは作成・再開、ASCENSION_ROOMSは最終Actの第2ボス有無を表す。判定マスクの一致だけで全10効果が実機確認済みとはしない。

Setupは既存local/paths.txtの3行を保持する。旧設定にAscensionMaskを追加し、指定がない既存値を維持する。ゲーム・セーブのルートはコピー・統合しない。設定・旧MODはmods外に保全し、ビルド失敗では既存導入に触れず、導入失敗では旧版へ戻す。導入はDLL・manifest・ローカル生成パス指定の3ファイルだけで、ゲームDLLやテスト用Harmonyは含めない。

中断ランには独自Modifierが含まれるため、再開にはSelectMODが必要。まずは検証用のプロフィール／ランで試す。0.1.0の保存設定テスト用ランには、現在のアセンション設定を後付けしない。

無効化するときはゲームを終了し、MODをmods外へ退避する。

```powershell
.\scripts\Disable.ps1
```

セーブと設定は削除しない。SelectMODを含む中断ランは、再導入するまで再開しない。

## 開発用の検証

本体だけビルドする（実ゲームDLLが必要）。

```powershell
.\scripts\Build.ps1
```

ゲームを使わない独立契約・Harmonyテスト。

```powershell
dotnet run --project .\tests\SelectMOD.ContractTests -c Release
```

診断スクリプトの模擬テスト。

```powershell
.\tests\Scripts.Tests.ps1
```

インストーラーの模擬テスト（実ゲームや実セーブを使わない）。

```powershell
.\tests\Setup.Tests.ps1
```

Cloudではテスト用の最小契約型を使って本体コードの経路を検証している。本番プロジェクトは実ゲームDLLのみを参照し、代用型を使ってビルド成功とはしない。実DLLビルド・ローダー・実保存・パケット・実機マルチは別々に確認する。
