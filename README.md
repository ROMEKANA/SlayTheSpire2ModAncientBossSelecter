# SelectMOD製作メモ

自分用の非公開向けメモ。現在は **0.6.0：ソロ＋マルチ試験版**。0.5.0は「行けてた」との利用成功報告を受領（組み合わせや完走・保存再開の網羅確認とは別）。今回はホスト編集・ゲスト表示・開始時の同期設定固定・マルチ保存再開を実装した。**0.6.0の実ゲームDLLでのビルドは成功報告済み（警告・エラー0）。Steam投稿完了、実機マルチ、実保存・再開は未確認。** Cloudの独立テスト185項目、別々の.NETプロセスでのゲスト試験、公開Godot APIコンパイル、スクリプト検証は成功。

0.2.0は手元でビルド・導入できたが、開始後に固まったとの報告があった。ログは設定選択までで途切れており、停止原因は断定できない。まず動くソロ選択MODを優先し、個別アセンションのフックを外した。通常の累積アセンションはゲームの設定をそのまま使う。

0.3.0は手元でビルド・導入・開始まで進んだが、ボスが反映されないとの報告があった。ログでは7回とも変更なしとして開始しており、変更処理には入っていなかった。どの操作で変更が失われたかは不明。0.4.0では確認ダイアログを廃止し、画面上の選択→開始時の設定→確定結果をそれぞれログに残す。

## Workshopで知人に配る（0.6.0）

配布用の日本語説明・サムネイル・公式アップローダー用スクリプトを用意した。**ゲームの選択・同期機能とバージョンは0.6.0のまま**。配布対応として、設定ファイルがない初回でも設定欄を使えるようにした。公開範囲は **限定公開（unlisted）**。検索向けの一般公開ではなく、リンクを知っている人が見てサブスクできる設定で、リンクの転送先もアクセスできる。「自分のみ（private）」とは違う。

作業場所はこのリポジトリのルート。Windows x64、既存の.NET 9 SDK、対応ゲーム本体を使う。公開するSteamアカウントでSteamを起動・ログインしておく。友人にはSDKもこのリポジトリも不要。

配布内容を作って確認する（アップロードなし。最後にエクスプローラーで開く）。

```powershell
.\scripts\Publish-Workshop.ps1 -PrepareOnly
```

Steamに限定公開で登録する（ビルド・検査・公式ツール取得も自動）。以後の更新も同じコマンド。

```powershell
.\scripts\Publish-Workshop.ps1
```

生成先は `local/workshop/SelectMOD/`。`content/` の中身は **SelectMOD.dll と SelectMOD.json の2つだけ**。手動導入先のフォルダーをそのままアップロードしない。個人用の `SelectMOD.paths.txt`、config、ログ、ゲームDLLは含めない。設定・セーブ・手動導入先はこのスクリプトでは変更しない。公開説明は [workshop/description.txt](workshop/description.txt)、画像は `workshop/image.png`。

公式 [MegaCrit/sts2-mod-uploader](https://github.com/MegaCrit/sts2-mod-uploader) のWindows x64版v0.2.0を取得し、公開されたSHA256で検証してから起動する。アップロード成功後に表示されるWorkshop URLを開き、**公開範囲が限定公開になっていること**とSteam規約同意の表示を確認してから友人へURLを送る。公式ツールは項目の設定失敗を警告だけで続行する場合があるため、成功表示だけで範囲の反映を断定しない。

**`local/workshop/` は消さない。** `SelectMOD/mod_id.txt` と `SelectMOD-item-id.txt` が同じ投稿への更新に必要。別PC・新しいチェックアウトへ移る場合はこのフォルダーを保持するか、既存ページのIDを指定する。

```powershell
.\scripts\Publish-Workshop.ps1 -WorkshopItemId 既存ページの数値ID
```

失敗時は `local/workshop-prepare-report.txt` または `local/workshop-upload-report.txt` を送る。途中まで作成された可能性があるときは重複防止のため自動再投稿しない。自分のWorkshopに項目があれば上のID指定で再開する。**項目が作られていないことを確認できた場合だけ**新規作成を再試行する。

```powershell
.\scripts\Publish-Workshop.ps1 -RetryNewItem
```

### Steam初期化で NativeCommandError になった場合

`Setting breakpad minidump AppID = 2868840` はSteam SDKが標準エラー出力に書く初期化メッセージ。この行だけではアップロード失敗を示さない。旧スクリプトはWindows PowerShell 5.1でこれを停止エラーとして扱っていた。修正版は標準出力・標準エラーを直接UTF-8で記録し、アップローダーの終了コードで判定する。処理中は出力をため、終了後に表示するので待つ。

旧エラーの後はアップローダーが裏で動いている可能性がある。修正版は実行中のModUploaderを検出すると再投稿を止める。終了を待って自分のWorkshopページを確認し、項目がある場合は上の `-WorkshopItemId`、ない場合は `-RetryNewItem` で再開する。`upload-pending.txt` やIDファイルを削除して無理に進めない。修正後も失敗したら `local/workshop-upload-report.txt` を送る（標準出力・標準エラー・終了コードをまとめて記録）。

### 自分と友人の導入

友人はURLでサブスクし、ダウンロード完了後にゲームを再起動してMODを有効にする。設定欄は最初から利用でき、ログは通常 `%LOCALAPPDATA%\SelectMOD\selectmod.log` に出る。既に手動版がある自分のPCでは、ゲームを閉じて次を実行してからサブスク版を試す。同じ版の手動版が残るとゲームがWorkshop版を無効にするため。既存の設定・セーブは保持される。

```powershell
.\scripts\Disable.ps1
```

Workshop版は個人用パスファイルを含まないため、設定・ログは標準の `%LOCALAPPDATA%\SelectMOD` を使う。手動版で別の設定場所を選んでいた場合、その設定は残るが自動移行しない。`SELECTMOD_CONFIG_DIR` を設定している場合は従来どおりそちらが優先される。

マルチは全員のゲーム版・MOD版をそろえ、**Standardカスタムランを2～4人**で作成する。ホストが選択、ゲストは確認のみ。まず新規ランで試す。ゲーム更新で対応DLLが変わると初期化を止めるため、同じ0.6.0という表示だけで対応判断しない。

**Cloudでは実ゲームDLLを使った配布ビルド、Steamへの投稿・サブスク、実機マルチは未実施。** スクリプトは手元のゲームDLLを検査・ビルドしてから投稿する。独立テスト185項目、公開Godot APIコンパイル、Workshop用スクリプトの模擬試験は別の検証であり、Workshop実配信の成功を意味しない。

## 使えるようにした機能

- キャラクター選択画面の右上に「▶ SelectMOD設定」を表示する。押すと大きな設定欄を開き、もう一度押すと閉じる。最初は折りたたんだ状態。Standardカスタムラン画面にも追加する。
- 閉じても選択内容は維持し、見出しに「指定あり」または「ランダム」を表示する。設定後は閉じてゲームの開始ボタンを押す。閉じた設定欄は見出しの高さまで縮む。
- 各Actの主ボスとエンシェントを選ぶ。先頭は「ランダム」。Act1のボスは「ランダム、血族、滝の巨人、…」の順で、残りもモデルIDで固定する。
- 選ぶと即座に次回設定へ反映する。確認ダイアログはなく、ゲームの通常の開始ボタンで出発する。「全てランダムに戻す」ボタンもある。
- ソロの次回設定はキャラ変更・画面の出入りでもゲーム終了まで保持する。ゲームを再起動したときはランダムに戻る。マルチはロビー単位で管理し、ホストのソロ次回設定から初期化するが、ホスト・ゲストのソロ設定へ書き戻さない。開始済み・保存済みランの設定には影響しない。
- **1つでも指定した場合、入口は通常ランでも内部的にはカスタムラン扱いになる。** 実績・進行等の扱いはゲーム標準のカスタムラン規則に従う。全項目が標準なら元のラン種別を保つ。
- **全Actのボス・エンシェントを各Actで固定指定できる（実験）。** 未解放・別マップの候補も含む。本来そのActに出ない候補は「[別Act]」付きで表示。例えばAct1にAct3のボスやエンシェントを指定できる。同じエンシェントの複数Act指定も可能。
- 別Actへ移した敵の強さ・報酬をSelectMODで調整はしない。専用の背景・進行条件・重複報酬等は実機確認が必要。まず新規の試験ランで1か所ずつ試す。
- 「ランダム」はゲームの標準抽選で、未解放・別マップの候補を無理に抽選対象へ追加しない。固定指定した場合だけ差し替える。
- A10の第2ボスは標準抽選を維持する。指定した主ボスと重なる場合だけ、元の主ボスを第2ボスに入れ替える。第2ボスを直接指定する画面はまだない。
- 通常の全Act生成後、マップ生成前に指定を反映する。追加でゲームの乱数を消費しない設計。
- 指定内容と確定した出現先をランに保存し、再開では再抽選せず照合する。

外部MODへの依存はない。ゲーム標準ローダーと同梱Harmonyを使用し、affects_gameplay=true。MOD ID／DLL名はSelectMOD。調査済みSteam Build IDは26660232で、導入・起動時にDLLの指紋を照合する。未知のDLLでは停止する。

## ネオーが報酬を出さなかった問題

ゲームにはModifierがあるとネオー専用の選択肢へ切り替える分岐がある。SelectMODは選択・確定結果を保存するためだけにModifierを使い、ネオー用の行動は定義していないため、この分岐で通常報酬が出なくなる経路があった。

0.5.0では、ネオーの選択肢生成中の一覧参照だけからSelectMOD自身の保存専用モデルを除外する。他MODのModifierやネオー報酬は維持し、実際のラン設定・保存用の一覧は変更しない。カスタムラン扱いは引き続き維持。実機で通常報酬が戻るか確認する。

## 既存MODに依存するか

使いやすさや安定性に役立つなら、依存を追加する方針に変えてよい。今回はBaseLibのModConfig・ドロップダウン実装を確認したが、主にMOD設定メニューを作る仕組みで、キャラ選択画面への配置とランへの設定受け渡しは別途必要だった。そのため0.4.0では追加していない。独立性のために失敗を繰り返す方針ではなく、今後共通の設定・翻訳等で手数が減るなら採用を再検討する。

## 通常ラン扱いへの変更

現在は通常ランのキャラ選択画面から使えるが、指定を入れたランの内部区分はカスタム。通常ラン扱いにすること自体は可能。ただし、実績・進行・チュートリアル・履歴・保存再開の分岐にも関係する。動作した0.4.1のルールを維持し、今回はマルチ対応を優先し、通常ラン化は今後の別変更として、記録と既存セーブの扱いを確認してから対応する。保存済みのカスタムランを自動変換はしない。

## 更新・ビルド・導入

Windows PowerShellで、このリポジトリ直下を開いて実行する。ゲームは終了しておく。

.NET 9 SDKがない場合だけ追加する（SDK 10だけではglobal.jsonを満たさない）。

```powershell
winget install --id Microsoft.DotNet.SDK.9 --exact
```

リポジトリを更新する。

```powershell
git pull --ff-only origin main
```

テスト・実ゲームDLLでのビルド・導入をまとめて実行する。

```powershell
.\scripts\Setup.ps1
```

初回はlocal/paths.txtを作り、3行でゲームルート・セーブのルート・MOD設定ディレクトリを管理する。既存のパス・設定は維持する。以前設定欄を無効にした場合、次のコマンドで再び有効にして導入する。

```powershell
.\scripts\Setup.ps1 -SelectionDialog $true
```

設定のSelectionDialogは互換性のため名前を残している。ソロの設定欄・新規ランへの指定の適用を切り替える。マルチの設定欄は同期確認のため表示し、ゲストのこの設定がfalseでもホストの確定設定を適用する。旧AscensionMaskは保全するが使用しない。以前の-Ascensions引数は廃止。ボスやエンシェントはセットアップ時ではなくゲーム内で毎回選ぶ。

Setupはビルド失敗なら既存導入を置き換えず、導入途中の失敗なら旧版へ戻す。旧MODと設定のバックアップはmods外へ置く。配置するのはDLL・manifest・生成パス指定の3ファイルだけ。ゲームDLL・テスト用Harmony・GodotSharpを同梱しない。セーブをコピー・統合・書き換えしない。

## マルチの試し方（0.6.0試験版）

**全員に同じ0.6.0を導入し、ゲームと候補に影響するMOD・設定も揃える。ホストだけの導入では使えない。** 導入コマンドは上と同じ。ソロの導入方法・保存形式は維持している。

1. ホストが**カスタムのマルチランを作成し、ゲームモードをStandard**にする。人数は2～4人。通常マルチの入口では開始を止める。
2. ホストが右上のSelectMOD設定を開いて選ぶ。ゲストはホストから届いた選択とrevision・短い照合値・Aレベルを確認する。ゲストの選択欄とリセットは変更不可。
3. 設定を変更するとホストの準備完了を解除する。設定後は折りたたみ、全員が通常の準備完了・開始操作を行う。ロビー画面のローカル設定ではなく、ホストの最終開始メッセージを各PCがランに固定する。
4. 最初はAct1ボスだけ指定し、両方のマップ・実際の遭遇・ネオーの報酬・進行を確認する。その後に別Act・A10・3～4人を試す。
5. 保存して全員がゲームを終了し、**作成時と同じ参加者全員**で保存したマルチランを再開する。選択・確定先が維持され、再抽選しないことを確認する。進行中の切断から直接再接続は未対応なので、保存終了後の全員再開を使う。

設定形式・版・候補一覧・確定設定が違う場合は、その側で開始を拒否する。古い受信・同じrevisionの内容違い・二重開始・開始後の編集も止める。標準のMOD不一致／State Divergence検出は無効にしていない。拒否後の全員の停止・切断・タイムアウトはゲーム標準の動作に従うため、実機で確認する。

マルチの保存ランは作成時のゲーム・SelectMOD・MOD構成を維持して試す。新しい候補や非互換な版へ更新した場合の自動変換はしない。大人数化MODや追加Act等との組み合わせは未検証。

各PCでログを回収する（各リポジトリ直下）。

```powershell
.\scripts\Export-ProbeReport.ps1
```

全員分の **local/selectmod-probe.txt** を、どれがホスト／ゲストか添えて送る。まず開始直後、その後は保存再開後にも回収すると比較できる。実機が1台でも通常のSetupはコンパイルと独立試験まで行えるが、それを実マルチ成功とはしない。

受け取った2ファイルをlocal/host-probe.txt、local/guest-probe.txtに保存した場合、照合できる。

```powershell
.\scripts\Compare-MultiplayerReports.ps1 -Reports .\local\host-probe.txt,.\local\guest-probe.txt
```

出力は **local/selectmod-multiplayer-compare.txt**。最後にエクスプローラーで選択表示する。MATCHは記録された設定・開始／再開条件・出現先・完了ログの一致で、通信・全ゲーム状態・戦闘完走の証明ではない。開始と再開のログを混ぜたり、最新試行が未完了の場合は成功扱いにしない。何かを固定指定したランが対象で、全ランダムのみでは出現先の比較データがないためINCOMPLETEとなる。

ホストを入れ替えた試験・3～4人・保存再開の詳細は[マルチの設計と確認項目](docs/MULTIPLAYER.md)。まず2人の短い試験で進める。

## 今回のソロ確認

1. ゲームを起動し、ソロのキャラクター選択画面右上の「▶ SelectMOD設定」を開く。
2. 最初はAct1ボスだけを指定し、エンシェントはランダムかネオーにする。折りたたんで新規開始し、ネオーの通常報酬と進行を確認する。
3. 次に別Actの候補を1か所だけ指定する。例えばAct1のエンシェントに「[別Act]」付き候補を指定して新規開始し、出現・選択肢・報酬・進行を確認する。別Actのボスは実際のボス戦も確認する。強さをSelectMODで調整はしない。
4. 保存・終了後、再起動して同じランを再開し、確定結果と進行が維持されることを確認する。「全てランダムに戻す」とA10の第2ボスは別途確認する。

途中で止まる・画面が出ない・選択が反映されない場合は、最後にできた操作を一言添えて次のログを送る。

ログを1ファイルにまとめ、最後にエクスプローラーでそのファイルを選択表示する。

```powershell
.\scripts\Export-ProbeReport.ps1
```

送るファイルは **local/selectmod-probe.txt**。ビルド・導入・MODログと、見つかった場合はゲームのlogs/godot.log末尾も含む。エクスプローラーが起動できなくてもレポートは残る。自動処理で画面を開きたくない場合は-NoOpenを付ける。

SELECTION_PANEL_ATTACHEDが設定欄の追加、SELECTION_EDITが選択したID。開始時はSTART_ENTER → SELECTION_CAPTURED changed=True（選択IDつき）→ ENCOUNTER_PREPARED → ROOMS_GENERATION_BEGIN → ENCOUNTER_RESOLVED → ROOMS_RESOLVED → START_COMPLETEDが目印。ランダムのみならchanged=Falseになる。ネオーではNEOW_REWARD_VIEWに除外後のModifier数を残す。初期化中のNEOW_REWARD_PATCHは対象の処理を見つけて差し替えた記録。再開はENCOUNTER_RUN_LOADED。START_FAILED／ROOMS_FAILEDには例外を残す。ログの到達だけで実際の遭遇・進行確認済みとはしない。

無効化する場合はゲーム終了後、MODをmods外に退避する。

```powershell
.\scripts\Disable.ps1
```

セーブ・設定は削除しない。SelectMODのデータを含む中断ランには、このMODの対応版が必要。

## 手元のゲームを調査する

WindowsのPowerShellで、このリポジトリのフォルダを開いて実行する。ゲームを終了し、Steamの更新が終わってから行う。

.NET 9 SDKがなければ追加する（調査ツールと本体ビルド用。SDK 10だけではglobal.jsonを満たさない）。

```powershell
winget install --id Microsoft.DotNet.SDK.9 --exact
```

PowerShellを開き直し、リポジトリ直下で調査スクリプトを実行する。

```powershell
.\scripts\Export-GameSources.ps1
```

初回はlocal/paths.txtを作成し、固定版のILSpyCmd 9.1.0.7988をlocal/ilspy9へ導入する（NuGetへの接続が必要）。ゲームDLLを短い一時フォルダ（OSのTEMP配下のsm-*）へ逆コンパイルして関連箇所を抽出するため、数分以上かかる場合がある。ゲームや生成プロジェクトは実行しない。

成功したら **local/selectmod-sources.txt** をこのチャットに送る。内容は以下。

- sts2.dll・0Harmony.dll・GodotSharp.dllのSHA-256、ファイルバージョン、取得可能ならSteam Build ID、runtimeconfig。
- 実在するソースの一覧と、ラン開始・ロード・保存・部屋生成・マップ・アセンション・通信に関係する主要な型。
- HasLevelや抽選・同期処理などの検索結果と前後のコード。既定では最大2500箇所で、打ち切り件数を明記する。完全な呼び出し解析ではない。

セーブ・ゲーム設定・MOD導入先は読み書きしない。変更するのは作業用local/配下、OSのTEMP配下に作成する専用一時フォルダ、指定したパスファイルの初回作成だけ。DLLのハッシュを前後で確認し、失敗・更新検出時は前回の正常レポートを置き換えない。成功時は今回の一時ソースを削除し、前回のレポートは別名で残す。生成ソース・DLL・診断結果はGit対象外。

失敗したら **local/selectmod-export-error.txt** を送る。調査に使った一時ファイルも残す（場所はエラーファイルのPartial output欄）。PowerShell自体に実行を拒否された場合はスクリプトが起動していないため、このエラーファイルは作成されない。

### ゲームの場所が標準と違う場合

local/paths.txtの3行は、ゲームルート、セーブのルート、SelectMODの設定ディレクトリ。既存ファイルは上書きしない。ゲームが見つからなければ、1行目を実際の場所に直して再実行する。調査では2・3行目の場所にはアクセスしない。

パスファイルを開く（リポジトリ直下）。

```powershell
notepad .\local\paths.txt
```

別のパスファイルで調査する場合。

```powershell
.\scripts\Export-GameSources.ps1 -PathsFile 'D:\STS2-settings\paths.txt'
```

書式は[scripts/paths.example.txt](scripts/paths.example.txt)を参照。

### PowerShellの権限エラー

「スクリプトの実行が無効」は実行ポリシー、「署名されていない」は取得元のブロック、「アクセス拒否」は書き込み権限、「使用中」はファイルロックを確認する。

現在のポリシーを確認する（作業フォルダは任意）。

```powershell
Get-ExecutionPolicy -List
```

組織のポリシーで管理されていない場合、信頼できるスクリプトのために現在のPowerShellだけRemoteSignedにする。

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
```

取得元と内容を確認し、エラーで指定されたファイルだけブロックを解除する（例）。

```powershell
Unblock-File -LiteralPath .\scripts\Export-GameSources.ps1
```

MachinePolicy/UserPolicyは上書きしない。調査は通常のユーザー権限で行う。導入時の書き込み拒否では必要に応じて同じWindowsアカウントで昇格し、使用中ならゲームを通常終了する。広範囲のACL変更やプロセスの強制終了はしない。

起動前のポリシー情報をファイルに保存する（localが作成済みの場合、リポジトリ直下）。

```powershell
Get-ExecutionPolicy -List | Out-File -Encoding utf8 .\local\execution-policy.txt
```

